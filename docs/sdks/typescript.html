TypeScript SDK

The official NorthRelay TypeScript SDK (@northrelay/sdk 1.9.0) wraps the NorthRelay REST API with typed requests and responses, automatic retries for safe calls, and webhook signature helpers.

Most methods resolve to the API's response envelope, { success: true, data }, so read results from data:

Contact-list routes return { data } (and pagination for lists), and importCsv returns the import result directly. The return type of every method says which shape you get.

Emails are URL-encoded in paths for you. isSubscriptionError(error, code?) returns true for a NorthRelayError whose code is one of LIST_NOT_FOUND, TOPIC_NOT_FOUND, CONTACT_NOT_FOUND, CONTACT_BLOCKED, RECIPIENT_SUPPRESSED, RECIPIENT_UNSUBSCRIBED, NO_PENDING_CONFIRMATION, FREE_TIER_CONTACT_LIMIT or VALIDATION_ERROR (optionally a specific one). subscribe and resendConfirmation are never retried automatically, because a retry could send a second confirmation email.

Contacts

contacts.list() filters by status, tag, search, source, sortBy and sortOrder. It does not filter by list; use getListMembers(listId). contacts.create() does not record consent or fire webhooks; use subscriptions.subscribe() when a person signs up.

removeListMembers is the list owner removing someone (the membership is deleted). To record that a recipient asked to leave, use subscriptions.unsubscribe({ email, scope: 'list', listId }).

CSV import

importCsv accepts a Blob/File or the CSV text. mappings is required.

Topics (suppression groups)

A topic member is an address that opted out of that topic.

The member methods only edit the opt-out rows. For a recipient's own choice, prefer subscriptions.unsubscribe({ scope: 'topic', topicId }) or updatePreferences, which also update tagged lists and fire webhooks. bulkAddSuppressions(id, emails) and bulkRemoveSuppressions(id, emails) change up to 10,000 opt-outs at once.

Signup forms

forms.submit(id, values) posts answers keyed by fieldKey to a published form. From your own backend, subscriptions.subscribe() is usually the better choice.

Webhooks

The webhook routes return their own shapes rather than the { success, data } envelope, as shown above. create is not retried automatically. After rotateSecret, deliveries also carry X-NorthRelay-Signature-Previous (signed with the old secret) until previousSecretValidUntil, one hour later. events is typed as WebhookEventType[]. See Webhook verification for the receiving side.

Suppressions

reason is one of Bounce, Complaint, Unsubscribe or Manual. To record a recipient's own opt-out, prefer subscriptions.unsubscribe().

Templates and Brands (Studio)

Every template is a Studio design. Your dashboard templates use the application key "account" (ACCOUNT_APPLICATION); a product with an nr_app_ credential uses its own key.

templates and brandTheme are deprecated (sunset 30 April 2027). Template ids are design ids, so emails.send({ templateId }) keeps working.

Error Handling

API failures are thrown as NorthRelayError or one of its subclasses. Every error carries code, statusCode, fixAction and docsUrl when the API supplied them.

Automatic Retries

Read calls and idempotent writes are retried on network errors and HTTP 408, 429, 500, 502, 503 and 504, with exponential backoff from retryDelay (capped at 10 seconds) or the Retry-After header. Calls that could duplicate a side effect are not retried: subscriptions.subscribe, subscriptions.resendConfirmation, contacts.create, contacts.bulkCreate, contacts.importCsv, contacts.createList and the form create and submit calls.

Webhook Verification

NorthRelay signs each delivery with HMAC-SHA256 of the raw body in the X-NorthRelay-Signature header. Verify against the raw body, before parsing it.
