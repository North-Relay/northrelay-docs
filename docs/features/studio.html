NorthRelay Studio

NorthRelay Studio is where your email templates and brands live. Every template, whether you build it in the dashboard, adopt it from the gallery or create it from code, is a versioned design: you edit a draft, review it, and publish an immutable release that sends use. Studio is included from the Micro plan ($12/mo).

Open it from the sidebar: Studio → Overview, Templates, Brands, Assets, Applications and Activity.

What you get

Test sendsSend yourself a test from a verified sender, safely retried with an idempotency key.

ApplicationsProducts that send through NorthRelay (for example Alteriom Command Center) keep their own templates and brands under an application key, reached with a scoped nr_app_ credential.

Account templates and application templates

Your own templates, the ones you create in the dashboard, belong to the reserved application account. Products can own templates under their own application key. The two differ in how they treat brands and variables:

Account templates (account)Application templates (e.g. command-center)
BrandUses the bound brand live: edit the brand and the next send uses it.The brand is frozen in each release. After a brand change, the brand editor lists the templates to publish again and can publish them for you.
VariablesLenient: a missing variable renders empty, extra variables are ignored.Strict: required variables must be present, unknown variables are refused.
SenderOptional on the template; the brand sender is the default, and a send can choose another verified sender.Must be one of the credential's allowed senders.

Sending with a template

Use the template id with the email API. Nothing changes if you already send this way:

The send uses the template's live release. A retired template is refused with TEMPLATE_RETIRED, a template that was never published with TEMPLATE_NOT_PUBLISHED, and missing required variables with MISSING_TEMPLATE_VARIABLES; each error names the fix.

Campaigns pick a template in the campaign wizard and render it with the contact's details, the brand and the unsubscribe links.

From code

Everything in Studio is available through /api/v1/designs, the SDKs and the MCP server.

Every response is { success: true, data } or { success: false, error: { code, message } }. Writes carry expectedRevision (designs) or expectedUpdatedAt (brands), so two editors get a 409 REVISION_CONFLICT instead of overwriting each other.

New releases render with handlebars-email-v2: values are escaped, template sources are checked on save and publish (no script, iframe, form, event handlers or javascript: links), and MJML styles and Outlook conditional comments are kept.

The TypeScript and Python SDKs expose these as client.designs, and the MCP server as the *_email_design*, *_email_brand* and *_email_asset* tools.

Installing templates into another account

A product that sends through its users' own NorthRelay accounts can ship its templates as a manifest: export the application's manifest from the product's account, then apply it with the user's credential into their account (dryRun: true to show the plan, then dryRun: false, publish: true to install and publish in one call). The export's version tells you when an installed copy is behind.

Embedding Studio in your product

@northrelay/studio-react renders the same Studio screens (template library, workspace, brands) inside another React app. Your server proxies the Studio API with an application credential, so no NorthRelay key reaches the browser. Alteriom Command Center uses it.

Legacy APIs

/api/v1/templates and /api/v1/brand-theme keep working until 30 April 2027 and return Deprecation, Sunset and Link: rel="successor-version" headers. Every existing template is now a Studio template with the same id, so templateId values in your code stay valid. Move template and brand management to /api/v1/designs.
