NorthRelay Studio

Programmable email designs — brands, versioned releases, rollback and idempotent sends your application calls by key

NorthRelay Studio

NorthRelay Studio is the part of the platform that turns email templates into versioned, brandable releases your product sends by key. It is included from the Micro plan ($12/mo) and shares its template capacity (25 on Micro, 100 on Pro, 500 on Scale).

Studio is the engine behind NorthRelay's own operational digests, and the same engine is available to every account through the dashboard and the /api/v1/designs API.

What you get

CapabilityWhat it means for you
BrandsColours, logo, fonts, sender defaults, footer and social links, exposed to every template as {{theme.*}} variables. One change rebrands every design.
DesignsA template and brand pair owned by one of your applications, addressed by a stable applicationKey / key / locale tuple instead of an opaque id.
ReleasesPublishing creates an immutable snapshot of template and brand. Sends reference a release, so a later edit never changes mail already in flight.
Revision checksEvery update carries expectedRevision. Two people editing the same draft get a 409 REVISION_CONFLICT instead of silently overwriting each other.
RollbackAny earlier release can be copied forward as a new release in one call.
Previews with sample dataRender the draft, the published release or any version with real variables, or ask Studio to synthesise samples from the variable schema.
Idempotent sendsSends require an Idempotency-Key. Retries return the original receipt, a conflicting payload is refused, and an uncertain submission is reported rather than resent.
DeliveriesEvery send keeps the release it was rendered from, plus the recorded delivery, bounce and open events.
Application credentialsnr_app_ keys scoped to specific applications and verified sender addresses. A credential can never send as a domain it was not issued for, and can never mint another key.
ManifestsExport every design and brand as a manifest, review the plan, and apply it atomically from CI.

Two ways to work

In the dashboard. Open Sending → Brands & themes to create a brand with the wizard, then Sending → Templates to design with Handlebars variables, preview with sample data and publish. The template gallery gives you starters for authentication, notifications, billing and marketing.

From code. Create an application credential under Settings → API Keys, then drive the same objects through the API:

API surface

MethodPathPurpose
GET/api/v1/capabilitiesPermissions, sender and application restrictions, plan capacity
GET, POST/api/v1/designsList accessible designs / create a draft
GET, PATCH/api/v1/designs/{id}Read / replace the draft with expectedRevision
POST/api/v1/designs/{id}/previewRender the draft, the published release or a version
POST/api/v1/designs/{id}/publishPublish expectedRevision
POST/api/v1/designs/{id}/rollbackCopy an earlier version into a new release
GET/api/v1/designs/{id}/releasesImmutable release history
POST/api/v1/designs/{id}/sendSend the published release or a version
GET/api/v1/designs/{id}/deliveriesSubmission receipts and recorded events
GET, POST/api/v1/designs/manifestExport, plan or atomically apply drafts
POST/api/v1/designs/assetsUpload an immutable public logo
GET, POST/api/v1/designs/brandsBrands scoped to the credential's applications

Every response is { success: true, data } or { success: false, error: { code, message } }. Rendering uses handlebars-safe-v1: strings are escaped, URLs must be HTTPS, if, unless and one-level each are supported, and script, iframe and form content is removed.
