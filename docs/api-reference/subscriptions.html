Subscriptions API

Subscribe and unsubscribe recipients, run double opt-in, read and update preferences across lists and topics.

Subscriptions API

The Subscriptions API is the one place to change who receives which mail. Use it from your own application to build newsletter signups, a preference page inside your product, or server-side opt-outs. Every call applies the same rules as NorthRelay's hosted forms, unsubscribe links and preference centre, and fires the same webhooks.

For a walkthrough of how the pieces fit together, see the Mailing Lists guide.

Concepts

TermWhat it isManaged with
ListAn audience you send campaigns to. A contact is either a member or not./contacts/lists
TopicA category of mail a recipient can opt out of (for example "Product updates"). Stored as a suppression group. A member row in a topic means the address opted out of that topic./suppression-groups
Global unsubscribeThe recipient wants no marketing mail at all. The contact status becomes UNSUBSCRIBED and an account-level suppression with reason Unsubscribe is added.This API

Rules the API enforces for you:

  • Subscribing to a topic means removing the recipient's opt-out for it. Opting out of a topic also removes the recipient from every list tagged with that topic.
  • Unsubscribing from a list keeps the membership history (the membership is marked removed). Removing a member as the list owner deletes it (see list members).
  • Someone who unsubscribed is never re-added silently. You must pass "resubscribe": true, and you should only do so after fresh consent.
  • Bounce, complaint and manual suppressions are never lifted by a subscribe call.
  • Contacts with status COMPLAINED or CLEANED cannot be resubscribed.

Authentication and scopes

All endpoints in the first part of this page take an API key: Authorization: Bearer nr_live_.... Restricted keys need these scopes:

EndpointScope
GET /subscriptions/{email}contacts:read
POST /subscriptions, POST /subscriptions/unsubscribe, PATCH /subscriptions/{email}, POST /subscriptions/{email}/resend-confirmationcontacts:write

A key without the scope receives 403 SCOPE_INSUFFICIENT; a missing or invalid key receives 401.

The public endpoints for unsubscribe pages you host yourself (POST /unsubscribe, POST /unsubscribe/one-click) take the signed token from the unsubscribe link instead of an API key. See Unsubscribe links.

Subscribe

Create or update a contact, add it to lists, opt it into topics and record consent. With doubleOptIn: true NorthRelay emails a confirmation link and the contact stays PENDING until the recipient clicks it.

Returns 201 when the contact was created, 200 when it already existed. Repeating the same call is safe: nothing is added twice.

Unknown fields are rejected.

Consent evidence

NorthRelay stores the consent source (api for this endpoint), the time, and whatever you pass in consent:

FieldTypeDescription
consent.ipstringThe subscriber's IP address. Pass it from your server: NorthRelay only sees your server's address. Max 64 characters.
consent.userAgentstringThe subscriber's browser user agent. Max 1,024 characters.
consent.textstringThe exact wording the subscriber agreed to (for example the checkbox label). Max 2,000 characters.

Together these are the record of express consent that CASL (Canada) and GDPR (EU) expect you to be able to produce. Consent is recorded when the contact is created, when it is resubscribed, or when it had no consent record yet; a repeat subscribe does not overwrite earlier evidence. Read it back with Get subscription status.

Double opt-in flow

  1. Your app calls POST /subscriptions with doubleOptIn: true. The contact is PENDING.
  2. The recipient receives a confirmation email with a link to https://app.northrelay.ca/c/<token>. The link is valid for 7 days.
  3. When they click it, the contact becomes ACTIVE, a contact.confirmed webhook fires, and the recipient is redirected to your redirectUrl (or shown a confirmation page).

List memberships and topic opt-ins are applied immediately, so the contact appears in the list, with status PENDING, as soon as you subscribe it. Campaigns skip PENDING contacts until they confirm.

Unsubscribe

Opt an address out from your own server, for example when a user switches off a newsletter in your product's settings.

Request body

FieldTypeRequiredDescription
emailstringYesRecipient address
scopestringNoall (default), list or topic
listIdstringWhen scope is listThe list to leave
topicIdstringWhen scope is topicThe topic to opt out of
reasonstringNoFree text, max 500 characters. Stored on the contact for scope: all and included in the webhook.

What each scope does:

ScopeEffect
allContact status becomes UNSUBSCRIBED and an account-level suppression with reason Unsubscribe is added. Works even when the address is not a contact. An existing Bounce, Complaint or Manual suppression is kept.
listThe contact leaves that list and no longer receives campaigns sent to it. The membership is marked removed so the history stays visible. No effect when the address is not a contact.
topicThe address is opted out of that topic and removed from every list tagged with it. Works even when the address is not a contact.

Example response

changed is false when the address was already opted out, so the call is safe to repeat. contactId is null when the address is not a contact. A contact.unsubscribed webhook (with method: "api") fires only when something changed, plus list.member_removed for each list the contact left.

Get subscription status

Everything you need to render a preference page: the contact and its consent evidence, any account-level suppression, a pending double opt-in, every list membership (current and past) and every topic with a subscribed flag.

URL-encode the address once (jane%2Bnews%40example.com for jane+news@example.com); do not double-encode it. An address that is not a contact still returns 200 with contact: null, so you can show topic choices before someone subscribes.

Update preferences

Apply the choices from your preference page in one call. Returns the updated status in the same shape as Get subscription status.

Request body

Provide at least one of topics, lists or unsubscribeAll. Unknown fields are rejected.

FieldTypeDescription
topicsobject{ "<topicId>": true | false }. true removes the opt-out, false opts out (and leaves lists tagged with the topic).
listsobject{ "<listId>": true | false }. true joins the list (the address must already be a contact), false leaves it.
unsubscribeAllbooleantrue unsubscribes from everything. When set, topics and lists in the same request are ignored.
resubscribebooleanRequired when joining a list for someone who unsubscribed from everything
consentobject{ ip?, userAgent?, text? }, recorded when the change re-subscribes the contact. When resubscribe is true and consent is omitted, the request's IP address is recorded.

Notes:

  • Turning a topic back on does not lift a global unsubscribe. To bring back someone who unsubscribed from everything, join a list with resubscribe: true, or call Subscribe with resubscribe: true.
  • Changes fire contact.subscribed, contact.unsubscribed, list.member_added and list.member_removed webhooks with method: "api" or source: "API".

Example request

The response is the full status object shown under Get subscription status.

Unsubscribe links

Marketing mail from NorthRelay carries a signed, per-recipient unsubscribe token:

  • Campaign mail: the {{unsubscribe_url}} template variable, plus List-Unsubscribe and List-Unsubscribe-Post headers (RFC 8058).
  • API mail on a marketing message stream: NorthRelay injects the unsubscribe footer and the same headers automatically.

The unsubscribe link has the form https://track.north-pipe.ca/u/{token}. The token identifies your account and the recipient, so the endpoints below need no API key. Unsubscribes from API mail are attributed to your account and fire contact.unsubscribed even when the recipient is not one of your contacts.

Campaign templates can also use {{preferences_url}}, a signed link to NorthRelay's hosted preference centre where the recipient can choose topics or unsubscribe from everything.

If you host your own unsubscribe landing page, send the token and the recipient's choice here. This endpoint is public; the token is the authentication.

A bare contactId is no longer accepted: it let anyone who learned a contact id opt that person out. For opt-outs from your own server use POST /subscriptions/unsubscribe with your API key.

One-click unsubscribe (RFC 8058)

Mailbox providers (Gmail, Yahoo, Outlook) call the one-click URL from the List-Unsubscribe header when the recipient presses their built-in "Unsubscribe" button; NorthRelay's tracking service forwards those requests here. It unsubscribes the recipient from all marketing mail (webhook method: "one_click") and always answers 200, as RFC 8058 requires, even when the token cannot be resolved. A missing token returns 400.

GET /unsubscribe/one-click?token= does not unsubscribe. Link scanners and security gateways prefetch URLs, so a GET redirects (303) to the confirmation page, where the recipient presses a button.
